# VENU — рабочий контракт и конвенции проекта

Мультитенантная платформа продажи билетов на события. Полный план разработки — [PLAN.md](PLAN.md).

## Контракт работы (действует во всех сессиях, не переспрашивать)

**Весь код приложения пишет пользователь.** Ассистент даёт спеки, объяснения,
подсказки и ревью на баги. Ассистент НЕ пишет код приложения без явной просьбы —
даже если это «быстрее». Смысл проекта — усвоение, а не готовый артефакт.

**Инфраструктура и проверки — на ассистенте:** docker/compose, replica set Mongo,
конфиги тулинга (tsconfig/eslint/prettier/package.json), `stripe listen`,
curl-проверки, запуск тестов, чтение логов.

**Цель проекта:** портфолио под вакансию **Frontend Developer**. Бэкенд — прочная
основа, но глубина и полировка вкладываются во фронтенд (см. PLAN.md §«Перевес»).

## Порядок проверки (после каждого изменения, без исключений)

- Бэкенд: `docker compose exec server npm run typecheck` → `npm run lint` → curl
  на затронутый эндпоинт: успешный случай **и минимум один провальный** (отказ
  авторизации, провал валидации, несовпадение тенанта).
  Линт с анализом типов включён намеренно: `no-floating-promises` ловит ровно тот
  класс ошибок, на котором проект спотыкается чаще всего — незаваленный await у
  транзакций, вебхуков и «подметальщика».
- Фронтенд: `npm run typecheck` в `web/` → реальная проверка флоу в браузере.
- С Этапа 10: относящиеся тесты после каждого изменения логики Этапов 6–9.

## Закреплённый стек (август 2026 — не «последнее», а осознанно выбранное)

| | Версия | Почему именно так |
|---|---|---|
| Node (контейнер) | 24-alpine | Актуальный LTS «Krypton» |
| Node (хост) | 20.19.0 → **обновить до 24** | Ветка 20 вне поддержки с апреля 2026. Next 16 на ней работает (нужно ≥20.9), но лучше `nvm install 24` |
| TypeScript | **5.9.3** (не 7.x) | TS 7 — Go-нативный компилятор. `tsc --noEmit` у нас основной инструмент проверки, ломать его совместимостью плагинов незачем |
| Express | **5.2.1** | Async-ошибки форвардятся сами; `*` в путях → `/*splat`; `req.query` теперь getter |
| Mongoose | 9.9.4 | — |
| MongoDB | 8.0, replica set `rs0` | Одноузловой rs нужен для транзакций, не для отказоустойчивости |
| Next.js | 16.x, **App Router** | `params`/`searchParams` — промисы, их надо await'ить |
| React | 19.x | — |
| Tailwind | **4.x** | CSS-first конфиг через `@theme`, без `tailwind.config.js`. Ветка v3 заморожена на 3.4.19 |
| ESLint | 10.x, flat config | — |
| Модули | ESM, `nodenext` | В относительных импортах пиши `.js`, даже если файл `.ts` |

**UI-кит:** все компоненты пишем руками, включая Dialog/Select/Toast с focus-trap,
ARIA и порталами. shadcn/ui и любые готовые библиотеки компонентов — **нет**,
это осознанный отказ ради практики (см. PLAN.md §6).

## Раскладка

```
docker-compose.yml      mongo (rs0) + mongo-init + server
docker/mongo/rs-init.js идемпотентная инициализация replica set
.env / .env.example     единый env на корень
server/                 Express + TS, работает В контейнере
web/                    Next.js, работает НА хосте (быстрый HMR на macOS)
```

### Порты

BITO всё ещё запущен и держит 27017, 4000 и 5173, поэтому VENU разведён по своим
хост-портам. Внутри compose-сети порты стандартные — конфиг replica set и обращения
между контейнерами от проброса не зависят.

| Что | Внутри сети | На хосте |
|---|---|---|
| Mongo | `mongo:27017` | `localhost:27018` |
| Express | `server:4000` | `localhost:4001` |
| Next (на хосте) | — | `localhost:3000` |

Если BITO больше не нужен — `docker compose -f <путь-к-BITO>/docker-compose.yml down`,
после чего пробросы можно вернуть к стандартным.

Mongo и server — в Docker. Next — на хосте: следить за файлами через bind-mount
на macOS медленно, а `/api` rewrite из Next на `localhost:4000` работает одинаково
что из контейнера, что с хоста.

## Инварианты, которые нельзя нарушать

1. **Скоупинг по `tenantId` — на уровне сервисного слоя.** Не в роуте, не в модели.
2. **Чужой ресурс другого тенанта → `404`, не `403`.** 403 подтверждает существование.
3. **Клиент никогда не задаёт цену.** Присылает `{ticketTypeId, quantity}`, сервер
   пересчитывает всё остальное из базы.
4. **Редирект успеха Stripe — не доказательство оплаты.** В `paid` переводит только вебхук.
5. **`express.raw()` монтируется ДО `express.json()`** и только для роута вебхука.
6. **Индексы начинаются с `tenantId`** — единственное осознанное исключение
   описано в PLAN.md (публичная лента событий).
